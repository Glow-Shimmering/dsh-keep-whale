# 安装、备份与恢复

本插件当前从源码构建，以本地 `link:` 方式接入 DSH；尚未发布 npm 包。安装脚本适用于 DSH 桌面 profile 的 **pnpm 9 格式锁文件**，不会联网安装依赖或重启 DSH。

## 构建与安装

需要 Node.js 22.21 或更新版本。获取源码后，在项目目录运行：

```sh
npm ci
npm run verify
mkdir -p "$HOME/dsh-backups"
```

`verify` 包含类型检查、自动化测试和构建。确认 DSH 的所有任务已经处理完毕，**完整退出 DSH，包括后台进程**，再执行以下示例。按环境替换路径，备份目录须为空、其父目录须已存在：

```sh
node scripts/install.mjs \
  --profile "$HOME/.dsh/profiles/desktop" \
  --data-home "$HOME/.dsh" \
  --backup-dir "$HOME/dsh-backups/keep-whale-first-install" \
  --name 大肥鱼 --confirm-stopped
```

三个路径参数都须为绝对路径；`--data-home` 指 DSH_HOME，插件数据会放在其下的 `dsh-keep-whale` 目录。`--confirm-stopped` 表示你已确认 DSH 退出；脚本也检查旧插件的进程锁，若仍运行则停止。

- `--name` 设置初始伙伴名，可省略；重启后仍可在界面改名。
- 观察默认关闭。要在初始化时启用之后的新对话观察，可加 `--observe`；也可启动后在设置中开启。旧伙伴明确绑定的专属会话 ID 会加入排除范围；普通 DeepSeek 会话不会因旧 persona 绑定而被批量排除。
- 首次安装不猜模型价格。重启后在「设置 → 模型与预算」选择 DSH 已配置的线路，并自行填写输入、缓存命中、输出单价、单位和 B 站每日预算；B 站默认预算为 100 积分，可修改。普通聊天、记忆整理和非 B 站主动联系不受该上限拦截。
- `--tju` 是特定迁移辅助选项：仅当本机旧插件已保存的 tju 线路及 30／0.6／120 积分每百万 token、30 积分/元恰好与已确认信息一致时，才写入对应价格和每日 100 积分。其他用户不需要使用此选项；不匹配时脚本停止，不推测价格。

重新打开 DSH，在侧栏「陪伴伙伴」或浮层进入面板，核对模型、费用、观察范围和普通会话身份。首次使用从空白记忆开始；当前核心功能已有自动化检查，真实对话、长期陪伴与后台行为仍需在目标设备验证。

## 备份与切换

安装器备份 profile 的 `cordis.yml`、`cordis.patch.yml`、包配置和 pnpm 文件；通过 SQLite 在线 backup 保存旧记忆数据库的一致性副本，包括已提交 WAL。同时备份旧伙伴状态及浏览经历账本，不读取旧聊天，不导入旧记忆。旧浏览器账户目录和 Cookie 不复制，原位置保持不变。

脚本从 bundle 列表精确移除已知旧陪伴插件，保留其安装包与源码；为本插件添加本地链接与 pnpm 锁定项。其他皮肤、记账挂件及模型线路不应受影响。若 profile YAML 还有对旧插件的直接引用或非标准别名，脚本会停止并要求人工核对。已存在新插件数据、同名插件或不兼容的锁文件也会停止，避免覆盖。

同一备份目录重复安装时会核对配置、链接及初始化参数；一致则不重置数据，参数不同需在插件设置中修改。备份含私人配置，应限制访问，不要提交到 Git。源码目录须保留；后续包管理器可能重建 `node_modules`，若本地链接丢失，请先核对配置和备份再修复。

## 恢复旧版

先完整退出 DSH，使用安装时相同的路径与备份目录：

```sh
node scripts/restore.mjs \
  --profile "$HOME/.dsh/profiles/desktop" \
  --data-home "$HOME/.dsh" \
  --backup-dir "$HOME/dsh-backups/keep-whale-first-install" \
  --confirm-stopped
```

恢复前会核对安装后的包配置、pnpm 锁文件和链接。若它们在安装后被修改，脚本会拒绝自动覆盖，需人工合并。恢复只撤销本次安装对 profile 的修改，不覆盖或删除新插件数据、旧数据库或旧账户资料；备份仍保留。

## 记忆网络升级与回退

0.2 版在现有数据上迁移，不重置身份或聊天，不再运行首次安装器。升级前可用以下工具做一致性备份（备份目录必须不存在或为空）：

```sh
node scripts/backup-memory.mjs --data-home "$HOME/.dsh" --backup-dir "$HOME/dsh-backups/keep-whale-before-memory-network"
```

在已链接的源码目录构建新版本；确认 DSH 任务结束和草稿已保存，再退出并重开 DSH。首次加载 schema v2 时还会在数据目录生成 `keep-whale.before-memory-network-*.sqlite`。不要将这些文件上传公开仓库。

如需回退，先完整退出 DSH，包括后台进程：

```sh
node scripts/rollback-memory.mjs --data-home "$HOME/.dsh" --backup-dir "$HOME/dsh-backups/keep-whale-before-memory-network" --confirm-stopped
```

工具验证备份，并额外保存回退前数据库及 dist；恢复指定数据库和运行 bundle，不删除媒体、源码、密钥或其他插件。当前新产生的数据仍保留在回退前归档中，但恢复后的旧版仅显示备份时的数据。回退的 bundle 会在下一次源码构建时被覆盖；重新升级前先确认要使用哪一份数据库，不能把旧、新数据文件直接拼接。


## 0.2.1 凭据迁移与回退

本版不改数据库 schema，不重新认识伙伴。首次加载时将原 `embedding-secret.json` 迁入 DSH `credentials`，核对持久保存结果后再移除原文件；失败保留原文件，语义回想降级本地检索，设置中显示原因。密钥不进入数据库、备份工具输出或安装包；非秘密的能力检查标记另存 `embedding-credential-state.json`。宿主当前仍使用权限受限的明文凭据文件，不等于系统钥匙串加密。

有凭据冲突时可在语义设置中明确保存新密钥或清除；不需要通过伙伴聊天下指令。现有检查指纹与配置、密钥都一致时沿用检查结果，迁移本身不调用模型、不产生费用。

升级前照常备份数据库和 dist。若恢复到 0.2.0 或更早的 bundle，该版本无法读取新宿主引用；在旧版设置中重新填写密钥并检查，或恢复使用新版。回退工具不会把宿主密钥导出成旧明文文件，不要为此复制整个 `.credentials.yaml` 到仓库。凭据仍保留在宿主中，其它插件和 DeepSeek 模型凭据不受影响。

## 0.3 B 站升级与使用

升级前先使用上述在线备份工具保存现有数据库和运行 bundle；本版在同一伙伴数据库内增加 `bili_*` 表，不重置伙伴、聊天、互动或原记忆。确认 DSH 任务结束、草稿已妥善处理后再退出并重新打开，使新版代码加载。升级默认不启用自主浏览，也不会迁移旧插件的 B 站账号或浏览经历。

进入「逛 B 站 → 设置」，在单独打开的 Chrome 窗口手动登录伙伴小号，回面板检查昵称和 UID、明确确认小号并完成能力检查后，按需开启自主浏览。检查是对账号、图片能力声明与图像计费接口的核对，不证明真实视频一定成功。详细步骤、可用内容、暂停与费用规则见[逛 B 站](bilibili.md)。

伙伴 Chrome profile 保存在本机 `bili-browser/<伙伴 ID>/`，其登录状态不包含在常规 SQLite 或 bundle 备份中，不读取普通浏览器和旧插件 profile。它可能含敏感账号资料，迁移或清理前须单独妥善处理，不能上传公开仓库。退出登录会清 Cookie 并归档该 profile；不等同撤销服务端全部会话。

需要回退时，先完整退出 DSH，再用升级前的数据库和 bundle 备份执行回退工具。数据库回退到备份时刻；升级后生成的浏览记录会保留在工具创建的回退前数据库归档中，旧版本不会显示它们。profile 不会被常规回退工具合并或删除；不要为了回退而覆盖当前唯一的账号资料。回退前需另行记录要保留的数据，避免误以为旧版显示了全部新经历。
